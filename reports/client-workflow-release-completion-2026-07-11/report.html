Product Master

Quote pricing

Partial orders

Data and migration design

The old one-order-per-quote constraints were removed only after new order ownership fields were added and legacy records were backfilled. New orders use a serializable transaction and optimistic remaining-quantity update. This prevents two staff members from allocating the same quote balance and prevents a client retry from creating a duplicate order.

Deployment prerequisites

Not deployed in this implementation run. Railway deployment was explicitly deferred. Before touching the client environment, take a database backup, apply the migration to a staging copy, validate the legacy foreign-key backfill, set the listed environment variables, and run the same release gate against the deployed API.
  1. Set CORS_ORIGIN to the published web URL, PUBLIC_CATALOGUE_IMAGE_BASE_URL to the public API origin, and a persistent CATALOGUE_IMAGE_STORAGE_DIR or object-storage implementation.
  2. Deploy API and web from the committed revision. The Docker images now use lockfile-clean installation and provide /readyz and /api/health checks.
  3. Run database backup, migration deploy, and post-migration orphan/backfill validation before allowing traffic.
  4. Execute the client workflow smoke with a disposable account and test customer. Confirm login, quote, two partial orders, and a read-only order/dispatch check.
  5. Only then invite the client to acceptance testing. Do not run the destructive reset scripts against the client database.

Residual release risk

Dependency follow-up The targeted Nodemailer upgrade to 9.0.3 is included. The latest npm production audit still reports three high and several moderate advisories in legacy Nest GraphQL/WebSocket and Next bundled dependency paths. npm’s automated remedy recommends invalid major downgrades, so it was not applied. The production API exposes only POST GraphQL, disables Playground in production, restricts origins, and does not enable subscriptions; however, a planned framework dependency upgrade remains required for a clean audit.

Asset durability The code validates images and supports a configured persistent directory. Railway ephemeral storage is not suitable for durable product images unless the image directory is mounted persistently or replaced with object storage before the production rollout.

Earlier local user snapshot

The prior read-only audit of the configured local Marble Park database found 98 users: 37 active and 61 inactive. All 751 stored sessions were expired at that audit time. This is a local snapshot, not a current production count; production data remains unverified until Railway is restored and accessed under the deployment runbook.
